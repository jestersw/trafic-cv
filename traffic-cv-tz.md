# ТЗ: детекция, трекинг и подсчёт транспорта на видео с дорожных камер

## 1. Цель

Разработать систему, которая по видео с дорожной камеры:

- находит транспорт и пешеходов в кадре (детекция);
- присваивает каждому объекту постоянный номер и отслеживает его между кадрами (трекинг);
- фиксирует события: пересечение линии, подсчёт по классам;
- работает в реальном времени после оптимизации под edge-устройство.

Проект — портфолио под позицию CV/ML-инженера (детекция, трекинг, события в дорожном движении, edge).

## 2. Результат

- Репозиторий на GitHub/GitLab с кодом, конфигами и README.
- Видео-демо: рамки с классами и ID, линия подсчёта, счётчик, FPS.
- Отчёт о метриках качества и скорости до и после оптимизации.
- Модель в форматах PyTorch, ONNX и TensorRT (или квантованная).

## 5. Этапы и критерии приёмки

### Этап 1. Данные

- Скачать датасет, сконвертировать разметку в формат YOLO.
- Разделить на train/val/test по видео, не по кадрам: кадры одного ролика не должны попасть в разные выборки.
- Взять датасет под версионирование DVC.
- Провести EDA: распределение классов, размеры объектов, условия съёмки (день, ночь, дождь).

**Готово, когда:** `dvc pull` восстанавливает датасет, в README есть статистика по классам.

### Этап 2. Детекция

- Обучить baseline: YOLO small без изменений, pretrained на COCO.
- Дообучить на датасете с аугментациями albumentations: яркость и контраст, размытие, шум, имитация дождя и тумана, горизонтальный флип.
- Сравнить baseline и дообученную модель.
- Логировать эксперименты в MLflow/W&B.

**Готово, когда:** mAP@0.5 на test выше baseline, результаты в таблице.

### Этап 3. Трекинг

- Подключить ByteTrack к детектору.
- Для сравнения подключить SORT.
- Посчитать метрики трекинга на test-видео с разметкой треков.

**Готово, когда:** у объектов стабильные ID, MOTA и IDF1 посчитаны для обоих трекеров.

### Этап 4. События

- Линия подсчёта: счётчик пересечений по классам и направлениям.
- Дополнительно (по желанию): зона «остановка запрещена» — событие, если объект находится в зоне дольше N секунд.
- Вывод событий в CSV/JSON: время, ID объекта, класс, тип события.

**Готово, когда:** ручной подсчёт на тестовом ролике совпадает с автоматическим с ошибкой не более 5%.

### Этап 5. Оптимизация под edge

- Экспорт в ONNX, проверка, что результаты совпадают с PyTorch.
- Ускорение: TensorRT FP16, затем INT8-квантование с калибровкой.
- Замер FPS и mAP для каждого варианта.
- Дополнительно: запуск на CPU через ONNX Runtime как имитация слабого устройства.

**Готово, когда:** есть таблица «формат → FPS → mAP → размер модели», падение mAP после оптимизации не более 2–3%.

### Этап 6. Упаковка и документация

- CLI: `python run.py --video input.mp4 --model model.engine --line x1,y1,x2,y2`.
- Dockerfile с поддержкой GPU.
- README: задача, данные, архитектура, принятые решения и почему, метрики, ограничения, как запустить.
- Видео-демо.

**Готово, когда:** сторонний человек запускает проект по README с нуля.

### Этап 7. Перенос инференса на Rust

Имитация задачи из вакансии: прототип на Python переносится в финальный продукт на Rust.

- Rust-приложение загружает ONNX-модель через крейт `ort` (обёртка ONNX Runtime с поддержкой CUDA и TensorRT).
- Чтение видео и отрисовка — крейт `opencv` (биндинги OpenCV).
- Пре- и постобработка на Rust: resize и нормализация кадра, NMS.
- Трекер и подсчёт пересечений линии реализованы на Rust самостоятельно: SORT (IoU-сопоставление + фильтр Калмана) или упрощённый ByteTrack.
- Проверка на совпадение с Python-версией: одинаковые рамки на одних кадрах (с допуском), одинаковый счётчик на тестовом видео.
- Сравнение Python и Rust: FPS, задержка на кадр, потребление памяти, размер итогового бинарника или Docker-образа.
- Дополнительно: модуль трекера на Rust подключается к Python через PyO3 + maturin, чтобы ускорить Python-версию без полного переписывания.

**Готово, когда:** `cargo run --release -- --video input.mp4 --model model.onnx` выдаёт то же видео с рамками, ID и счётчиком, а в README есть таблица сравнения Python и Rust.

## 6. Метрики

| Метрика | Что показывает | Целевое значение |
| --- | --- | --- |
| mAP@0.5 | Точность детекции | Выше baseline |
| mAP@0.5:0.95 | Точность рамок | Выше baseline |
| MOTA | Общее качество трекинга | Сравнение ByteTrack vs SORT |
| IDF1 | Насколько стабильны ID объектов | Сравнение ByteTrack vs SORT |
| Ошибка подсчёта | Точность событий | ≤ 5% |
| FPS | Скорость обработки | ≥ 25 на GPU после оптимизации |
| Размер модели | Пригодность для edge | Сравнение до и после |
